# ADR-005: UX-улучшения панели — ресайз по сетке, фильтр содержимого, roll-up кнопка

**Статус:** Accepted  
**Дата:** 2026-06-28

---

## Контекст

В ветке `feature/fancy-windows` реализованы три улучшения поведения и UI панелей:

1. **Ресайз кратно сетке иконок** — при изменении размера панели мышью размер квантуется к ячейке иконок.
2. **Фильтр содержимого панели** — пользователь может скрыть ярлыки, папки или показать всё.
3. **Кнопка roll-up** — явная кнопка-тоггл для сворачивания/разворачивания рядом с SwitchView.

Каждое из них потребовало архитектурного решения.

---

## Решения

### Решение 1: `GridMetrics` как тестируемый вычислительный слой вне WPF (UI/Models)

Логика вычисления размера ячейки и квантизации вынесена в статический класс `GridMetrics`
(`UI/Models/GridMetrics.cs`) с двумя методами: `CellSize(double iconSize)` и
`Quantize(double value, double cell)`.

**Почему так:** методы не зависят от WPF-объектов (нет `DependencyObject`, нет `DispatcherObject`).
Статический класс без состояния тривиально тестируется через xUnit без запуска GUI. Логика
квантизации ранее была inline в `Resize_DragDelta`, что исключало тесты.

**Альтернатива:** оставить логику inline в code-behind. Тогда ресайз-логика непроверяема и
дублируется при добавлении новых мест вызова (например, клавиатурный ресайз).

**Trade-off:** лишний файл для двух методов. Окупается тестируемостью и переиспользуемостью.

---

### Решение 2: Аккумулятор без дрейфа в `Resize_DragDelta`

Предыдущая реализация квантизировала каждый `HorizontalChange`/`VerticalChange` дельты по
отдельности, что давало накопительный дрейф при нецелых значениях.

Новая реализация накапливает сумму дельт от начала жеста (`_resizeDeltaX`/`_resizeDeltaY`,
обнуляемых в `Resize_DragStarted`) и квантует **суммарное смещение**, применяя разницу к размеру.

**Почему так:** квантизация суммы, а не отдельных дельт, устраняет ошибку накопления — размер
после жеста всегда кратен ячейке сетки, независимо от числа событий мыши.

**Trade-off:** нужны поля-аккумуляторы в code-behind (`_resizeDeltaX`, `_resizeDeltaY`) и
обработчик `DragStarted` на всех 8 Thumb-ах. Альтернатив без накопления нет.

---

### Решение 3: Двухслойная модель данных для фильтрации — `_allItems` как источник правды в `BaseViewModel`

Для фильтра содержимого введён частный список `_allItems` в `BaseViewModel`, который хранит
весь несортированный набор файлов. Публичное свойство `FileItems` — это проекция через
`OnSourceChanged()` с применением текущего `ContentFilter`.

**Почему так:** без источника правды смена фильтра необратима — скрытые элементы теряются.
`_allItems` позволяет переключать фильтры без перезагрузки с диска. Логика проекции
инкапсулирована в `OnSourceChanged()`, вызываемом при изменении `ContentFilter` или при
добавлении/удалении файлов.

**Альтернатива A:** повторная загрузка с диска при смене фильтра — медленно, ломает Folder
Portals (они не сохраняют файлы на диск, а читают FS).

**Альтернатива B:** хранить все элементы в `FileItems` и скрывать через `Visibility` в
шаблоне — нарушает разделение модели и представления, усложняет подсчёт и сортировку.

**Trade-off:** `BaseViewModel` хранит лишний список в памяти. При типичном числе файлов
в панели (десятки–сотни) это несущественно.

### Решение 4: `PanelContentFilter` как enum в `UI/Models`, сериализуется в `ChildWindowModel`

Фильтр — enum `PanelContentFilter` (`ShowAll` / `HideAll` / `HideShortcuts` / `FoldersOnly`),
хранится в `ChildWindowModel.ContentFilter` (INPC, дефолт `ShowAll`), сериализуется в JSON
вместе с остальным состоянием панели.

**Почему так:** enum проще расширять (добавить значение — не Breaking Change в JSON при
`JsonStringEnumConverter`), сериализуется читаемо, тривиально привязывается через
`EnumEqualsConverter` в XAML-меню.

**Trade-off:** добавление нового значения enum требует обновления `OnSourceChanged()`.

---

### Решение 5: `IsRolledUp` — INPC через `SetField` (исправление регрессии)

В предыдущей реализации `IsRolledUp` было обычным авто-свойством в `ChildWindowModel` без
уведомления (`INotifyPropertyChanged`). Это означало, что привязки XAML (кнопка roll-up,
высота `ContentRow`) не реагировали на изменение значения через команды, и состояние не
отражалось корректно после восстановления из JSON.

Исправление: `IsRolledUp` переведён на паттерн `SetField` (как остальные INPC-свойства
`ChildWindowModel`), что обеспечивает корректное уведомление и двустороннюю привязку.

**Почему это ADR, а не просто фикс:** затрагивает инвариант проекта — все персистируемые
состояния `ChildWindowModel` обязаны быть INPC. Нарушение этого правила ранее было
незамеченным.

---

## Последствия

- `GridMetrics` — точка расширения для будущего клавиатурного ресайза и snap-to-grid при перетаскивании.
- `_allItems` в `BaseViewModel` создаёт контракт: любой код, добавляющий файлы в панель,
  обязан работать через `_allItems`, а не напрямую с `FileItems`.
- Все персистируемые свойства `ChildWindowModel` должны использовать `SetField` — нарушение
  теперь явно задокументировано как дефект (см. `IsRolledUp`).
- `EnumEqualsConverter` становится общим компонентом для будущих enum-биндингов в UI.
