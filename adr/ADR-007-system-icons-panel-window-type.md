# ADR-007: SystemIconsPanel — второй тип независимого desktop-window

**Статус:** Accepted  
**Дата:** 2026-06-28

---

## Контекст

Для паритета со Stardock Fences нужна вертикальная панель системных иконок у левого края рабочего
стола (аналог «системной панели» Fences). Панель отображает нативные системные объекты (Корзина,
«Мой компьютер», Сеть, Загрузки и т.п.) с их иконками, поддерживает двойной клик для открытия,
ПКМ → нативное контекстное меню Shell, drag-and-drop в Корзину, индикатор заполненности Корзины.

Существующая архитектура знает один тип desktop-окна — `ChildWindow` (Fence). `ChildWindow` несёт
логику снаппинга к сетке, roll-up, фильтра содержимого, inline-переименования, страниц (PageId),
Folder Portal (FileSystemWatcher). Добавление «системного» флага в `ChildWindowModel` потребовало бы
условных ветвей во всей этой логике и нарушило бы единственность источника правды для Fence-панелей.

---

## Решение

Реализовать SystemIconsPanel как **независимый второй тип desktop-window**, полностью изолированный
от инфраструктуры Fence-окон.

Конкретно:

- **Core:** `SystemIconKind` (enum), `SystemIconDescriptor` (запись: Kind, Label, PIDL).
- **Abstractions:** `ISystemShellService` (получить дескрипторы, открыть, показать контекстное меню,
  опросить Корзину), `RecycleBinState` (структура: ItemCount, SizeBytes).
- **Services:** `SystemShellService` — нативная реализация через PIDL, `IContextMenu` (COM),
  `SHQueryRecycleBin`, poll-таймер для индикатора Корзины.
- **UI:** `SystemIconsPanelModel`, `SystemIconItemModel`, `SystemIconSize` (enum, без инфикса Panel),
  `SystemIconsPanelViewModel`, `SystemIconsPanelWindow` (отдельное WPF-окно).
- **Управление:** `ISystemIconsPanelManager` / `SystemIconsPanelManager` — отдельный менеджер,
  не зависящий от `WindowManager` (который управляет Fence-окнами).
- **Persistence:** секция `SystemIconsPanel` в основном JSON-файле настроек через
  `IAppSettings.SystemIconsPanel` — отдельно от `ChildWindowsState`.
- **Z-order:** переиспользование `IDesktopIntegrationService.EmbedInDesktop` (WorkerW/Progman) — тот
  же механизм встраивания в слой рабочего стола, что используют Fence-окна.

  > ⚠️ **Уточнено [ADR-019](ADR-019-sidebar-top-level-virtual-desktop.md) (2026-09-02):** это решение
  > для `SystemIconsPanel` **отменено**. Боковая панель перестала встраиваться в `WorkerW` — она стала
  > обычным top-level окном с `Topmost="True"` (первопричина: `WorkerW` — единый слой на все
  > виртуальные столы, что делало настройку «Show on all virtual desktops» неработоспособной по
  > построению). Для fence-панелей (`ChildWindow`) это решение действует **без изменений** —
  > `EmbedInDesktop` по-прежнему единственный механизм их Z-order.

## Отклонённые альтернативы

### A: ChildWindow с флагом «системная панель»

Добавить в `ChildWindowModel` булев флаг `IsSystemPanel` и условно отключать snap, roll-up, PageId,
inline-rename, Folder Portal.

**Отклонено:** загрязняет модель Fence-окна условными ветвями. Нарушает инвариант «`ChildWindowModel`
— единый источник правды для Fence-панели». Усложняет тесты и будущие рефакторинги.

### B: AppBar (SHAppBarMessage)

Зарегистрировать панель как AppBar — тогда система автоматически резервирует место у края экрана.

**Отклонено:** AppBar резервирует экранное пространство и сдвигает рабочий стол — поведение,
противоположное подходу Fences (панель лежит поверх обоев, не меняет рабочую область). Кроме того,
интеграция с WorkerW-слоем при статусе AppBar не определена.

## Последствия

### Положительные

- **Изоляция:** SystemIconsPanel не затрагивает логику Fence-окон; изменения в одном типе не
  ломают другой.
- **Переиспользование:** `IDesktopIntegrationService.EmbedInDesktop` работает без изменений для
  нового типа окна — Z-order обеспечивается без дублирования нативного кода.
- **Тестируемость:** модели `SystemIconsPanelModel`/`SystemIconsItemModel` и persistence-логика
  покрыты 29 unit-тестами (xUnit) без WPF и нативного слоя.

### Отрицательные / риски

- **Нативная сложность:** `IContextMenu` (COM), работа с PIDL и `SHQueryRecycleBin` — нативный
  код, непроверяемый вне Windows. Ошибки манифестируются только на реальной системе.
- **Дублирование инфраструктуры:** два менеджера окон (`WindowManager` + `SystemIconsPanelManager`)
  и две точки регистрации в DI-контейнере. При добавлении третьего типа стоит рассмотреть общий
  абстрактный `IDesktopWindowManager`.
- **Poll-таймер Корзины:** опрос раз в N секунд вместо уведомления Shell — допустимый компромисс
  (API уведомлений о Корзине требует SHChangeNotifyRegister, что сложнее и не критично для UX).

## Manual verify (Win10 / Win11)

Следующее поведение не может быть проверено автотестами и требует ручной проверки на Windows:

1. Панель отображается за обычными окнами, но поверх обоев (Z-order WorkerW).
2. Нативные иконки системных объектов (Корзина, Компьютер, Сеть и др.) отрисовываются корректно.
3. Двойной клик по иконке открывает соответствующий системный объект.
4. ПКМ по иконке показывает нативное контекстное меню Shell (не кастомное WPF-меню).
5. Drag-and-drop файла в иконку Корзины перемещает файл в Корзину.
6. Индикатор Корзины меняется при добавлении/очистке файлов (с задержкой до poll-таймера).
7. Порядок иконок сохраняется после перезапуска приложения.
8. Панель скрывается/показывается через тоггл в трее или настройках.
9. DPI-масштабирование: иконки не размываются на дисплеях с высоким DPI.
10. Multi-monitor: панель остаётся на нужном мониторе при смене конфигурации.
11. Drag-reorder иконок внутри панели работает без артефактов Z-order.
