# Edit Layout UX — матрица ручной проверки (V-1…V-19 + доп. пункты ревью)

Артефакт Фазы 6 (`docs/PLANS/phase-6-edit-layout-ux.md` §7.2, `adr/ADR-026-edit-layout-mode.md`).
Фаза целиком про ввод — здесь только то, что **невозможно** закрыть `dotnet test`: реальное поведение
мыши/клавиатуры на `WS_EX_NOACTIVATE`-окнах слоя `WorkerW`, мультимонитор, DPI, WinForms-тултипы.
Машинно-проверяемая часть DoD (план §7.1) закрыта наборами `Unit/Models` (`LayoutGesturePolicyTests`,
`SnapGuideCalculatorTests`), `Unit/Services` (`LayoutEditModeServiceTests`), `Unit/Behaviors`
(`ResizeAffordanceGateTests`), `Unit/Theming` (`LayoutEditVisualsTests`), `Unit/Services`
(`TrayIconManagerTests`) — 1925/1925 тестов зелёные.

## Статус выполнения

> **Ни один сценарий этой матрицы не выполнен.** Среда разработки агента не имеет живого Windows-GUI,
> второго физического/виртуального монитора, возможности сменить DPI на лету и WinForms-рендеринга
> тултипов на disabled-пунктах меню — поведение проверено только компиляцией и unit-тестами (полная
> 12-кейсовая таблица истинности `LayoutGesturePolicy`, монотонность `LayoutEditVisuals` относительно
> Фазы 5, детерминизм `SnapGuideCalculator`). Все строки ниже находятся в состоянии **«не выполнено»** и
> требуют прогона человеком на Windows 10 и Windows 11 перед тем, как считать Фазу 6 закрытой по
> Global DoD (не только `[~]`).

## Где искать после каждого сценария

- Настройки: `IAppSettings.IsLayoutLocked` / `IAppSettings.NormalModeLayoutGestures` — `user.config`
  (не JSON-документ состояния, D-8).
- Диагностика (при `--diag`/Debug-сборке): `%LOCALAPPDATA%\DesktopOrganizer\Logs\app-*.jsonl`,
  категория `layout`, событие `LayoutModeChanged` — см. `Testing/diagnostics-log-events.md`.

## Процедуры и критерии

### V-1/V-2 — три точки переключения режима (DoD-3)

Все три точки (трей, меню заголовка панели, окно настроек + `Ctrl+E`) обязаны давать согласованное
состояние: включение в любой точке немедленно отражается галочкой во всех трёх. `Escape` в фокусе
панели — best-effort (тот же класс риска, что ADR-013 R1); не заменяет трей как гарантированный путь.

### V-7 — гарантированное завершение жеста при выходе из режима (DoD-4)

Начать resize за угол панели (курсор изменился на diagonal-resize). Не отпуская левую кнопку мыши,
переключить Edit layout → Normal из трея. Ожидание: `AbortResize(SourceChanged)` → `AbortDrag()` →
`ForceIdle()` отрабатывают синхронно с обработчиком `ModeChanged`; панель немедленно фиксирует текущую
геометрию (частично применённая на момент abort — это ожидаемо, ADR-021 `ShouldPersist =
AppliedDeltaCount > 0`), курсор возвращается в обычный, следующий клик по панели работает штатно без
«залипания» в состоянии `Resizing`.

### V-10/V-18/V-22 — snap-guides и мультимонитор (D-7, R-8)

Разместить две панели рядом на одном мониторе. В Edit Layout начать драг одной из них к краю/центру
другой — должно чувствоваться магнитное притяжение (без визуальной линии, см. известное ограничение
P6-6/DO-018 в ADR-026). Попытаться продавить панель сквозь соседнюю — «твёрдая стена» ADR-017 обязана
устоять при включённом guide-магните (R-8). Для V-22 — повторить у границы двух мониторов с разным DPI.

### V-13 — Lock layout (D-3)

Включить `Lock layout`. Проверить полную таблицу D-3: move/resize/вход-в-Edit-Layout заблокированы;
roll-up/rename/выделение/запуск-файла/drop/внутренняя ре-нормализация сетки (сменить `IconSize` при
включённом Lock — раскладка визуально подстраивается под новую сетку, это не нарушение Lock) — работают
штатно.

### V-20 — WinForms tooltip на disabled item

`ToolStripMenuItem.ToolTipText` присваивается корректно (закрыто `TrayIconManagerTests`), но WinForms по
умолчанию не всегда показывает тултипы на disabled-элементах в зависимости от версии рантайма/темы —
нужна визуальная проверка живьём, не только проверка присвоенного значения.

### V-21 — hot-plug/смена разрешения посреди жеста

Симулирует реальный сценарий ноутбука, подключаемого/отключаемого от внешнего монитора во время работы.
Снапшот `_dragMonitors` в `PanelDragMoveBehavior` берётся один раз на старте жеста (не на каждый
`MouseMove`, по соображениям производительности хот-пути) — проверяется, что устаревший снапшот в
худшем случае просто отключает guide-магнит на текущий жест (`Rect.Empty`), а не крашит приложение или
не телепортирует панель.
