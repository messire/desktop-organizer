# Performance Baseline — Measurement Procedure

Точный, повторяемый метод заполнения `performance-baseline-template.md`. Результаты обязаны быть
реально измерены на фиксированной машине — **не оценивать/не выдумывать числа**.

## 1. Подготовка фикстуры

Использовать `tools/perf/New-PerfFixture.ps1` для генерации `ChildWindowsState.json` с N панелями и
N×M фиктивными файлами во временной папке:

```powershell
./tools/perf/New-PerfFixture.ps1 -Panels 5 -ItemsPerPanel 100
```

Скрипт предварительно делает резервную копию реального файла состояния и умеет восстановить его
(`-Restore`) после замера.

## 2. Сценарии (соответствуют строкам шаблона)

| Сценарий | Panels | Items/panel |
|---|---:|---:|
| 3 panels / 100 items | 3 | ~33 |
| 5 panels / 500 items | 5 | 100 |
| 10 panels / 1000 items | 10 | 100 |
| 20 panels / 2000 items | 20 | 100 |

## 3. Warm-up и повторы

- Для каждого сценария: 1 прогрев (результат отбрасывается) + 3 замера.
- В таблицу идёт **медиана** из 3 замеров, не среднее (устойчивее к разовым выбросам ОС/антивируса).

## 4. Метрики и как их снимать

- **Startup** — от старта процесса до отрисовки последней панели. Использовать
  `tools/perf/Measure-Startup.ps1` (замеряет по `Process.StartTime` → событию появления последнего
  дочернего окна).
- **Working Set** — `Get-Process DesktopOrganizer.UI | Select WorkingSet64`, снято через 5 секунд после
  старта (после начальной раскладки панелей).
- **CPU idle** — усреднение `Get-Counter '\Process(DesktopOrganizer.UI)\% Processor Time'` за 60 секунд
  простоя (без взаимодействия с приложением).
- **CPU interaction** — тот же счётчик за 30 секунд скриптованного взаимодействия (открыть/закрыть
  панель, поресайзить, поскроллить список).

## 5. Машина и окружение

Зафиксировать в шапке `performance-baseline-template.md`: OS/build, CPU, RAM, GPU, число мониторов/DPI,
commit hash сборки. Замеры на разных машинах не сравнимы напрямую.

## 6. Native-изменения

Любое изменение, претендующее на performance-бенефит (в первую очередь Фаза 2/8), обязано приложить
before/after замер **на одной и той же машине** по этой же процедуре.

## 7. Статус

**Не выполнено в этой среде** — разработка ограничена `dotnet build`/`dotnet test`, живого Windows GUI
нет. `performance-baseline-template.md` оставлен пустым намеренно; заполняется человеком на Windows
10/11 по этой процедуре за один присест.
