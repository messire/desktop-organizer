# Versioned JSON Store — матрица ручной проверки (S-1…S-11)

Артефакт Фазы 4 (`docs/PLANS/phase-4-versioned-json-store.md` §8.2, `adr/ADR-024-versioned-json-persistence.md`).
Здесь — только то, что **невозможно** закрыть `dotnet test`: реальная пользовательская установка,
реальный инсталлятор, Fast User Switching, жёсткое отключение питания, Controlled Folder Access/AV,
реальные замеры времени старта. Машинно-проверяемая часть DoD (§8.1 плана) закрыта наборами
`Unit/Storage` (`AtomicJsonFileWriterTests`, `JsonApplicationStateStoreTests`, `StateMigrationRunnerTests`,
`Migrations/V1ToV2MigrationTests`, `Migrations/V2ToV3MigrationTests`, `GoldenMigrationTests`,
`LegacyStateImporterTests`, `StorageFileLockTests`, `SchemaContractTests`, `StateRestoreCommandTests`),
`Unit/State` (`PanelStateMapperTests`, `ApplicationStateServiceTests`), и `Integration/Services/DiConfigTests`.

## Статус выполнения

> **Ни один сценарий этой матрицы не выполнен.** Среда разработки агента не имеет живого Windows-GUI,
> установленного инсталлятора, второй пользовательской сессии Windows и возможности физически отключить
> питание машины — поведение проверено только компиляцией и unit/integration-тестами (D-6's пять
> инъецируемых точек отказа, все семь ступеней D-7, migration golden-фикстуры, `FileShare.None`
> per-handle семантика лока). Все строки ниже находятся в состоянии **«не выполнено»** и требуют прогона
> человеком на Windows 10 и Windows 11 перед закрытием фазы.

## Где искать после каждого сценария

- Store-файлы: `%LOCALAPPDATA%\DesktopOrganizer\State\application-state.json`(`.bak`, `.tmp-*`,
  `.corrupt-*.json`), `%LOCALAPPDATA%\DesktopOrganizer\.storage-lock`.
- Legacy: `%LOCALAPPDATA%\DesktopOrganizer_Url_*\<AssemblyVersion>\user.config`.
- Диагностика (при `--diag`/Debug-сборке): `%LOCALAPPDATA%\DesktopOrganizer\Logs\gestures-*.jsonl`,
  категория `state` — см. `Testing/diagnostics-log-events.md`.

## Процедуры и критерии

### S-1 — реальный апгрейд реальной установки (главный сценарий фазы)

1. Установить последний pre-Phase-4 релиз (0.3.x). Создать ≥5 панелей на ≥2 страницах (с разной
   геометрией/видом/сортировкой/цветом), сохранить ≥1 layout snapshot, включить системную панель
   (Recycle Bin и т.п.).
2. Закрыть приложение штатно («Выход» из трея — синхронный `SaveNow()` на `App.OnExit`).
3. Установить релиз этой фазы поверх, не удаляя предыдущий (обычный in-place апгрейд).
4. Запустить. Все панели/страницы/снапшоты/системная панель — на месте, включая геометрию и
   monitor-привязку.
5. Проверить: `%LOCALAPPDATA%\DesktopOrganizer\State\application-state.json` создан и содержит
   `schemaVersion: 3`; `user.config` **не изменён** со времени последнего запуска старого релиза
   (сравнить хэш/время модификации).

### S-2 — апгрейд без панелей

Установка, на которой приложение запускалось, но панелей никогда не создавалось (default state).
После апгрейда — `FirstRun` (диагностика, если включена) и валидный пустой документ, не `Quarantined`.

### S-3 — апгрейд с битым `ChildWindowsState`

Вручную испортить XML/JSON внутри `<value>` `ChildWindowsState` в `user.config` перед апгрейдом
(например, оборвать JSON на середине). Приложение должно стартовать без диалогов краша; повреждённые
данные либо не импортируются (см. `LegacySettingsImporter` per-key изоляцию), либо, если порча
произошла уже после первой миграции (испорчен `application-state.json`), — карантин
(`application-state.corrupt-*.json`), приложение стартует с пустым/частичным состоянием.

### S-4 — идемпотентность повторного запуска

После S-1, запустить приложение второй раз без изменений. Ожидание: `StateLoaded` (если включена
диагностика) со `status: Loaded`, `migrationsApplied: 0` — миграция не повторяется на уже мигрированном
документе.

### S-5 — откат, сценарий A (`Storage/rollback.md`)

Установить 0.3.0 поверх релиза этой фазы. Ожидание: старый build читает `user.config` напрямую и
показывает layout **на момент миграции** (см. `rollback.md` сценарий A) — не пустое состояние, но и не
обязательно последнее. Изменения, сделанные после миграции, не теряются — они ждут в
`State\application-state.json` до повторной установки нового релиза.

### S-6 — откат, сценарий B

Установить более старый релиз, который уже понимает формат JSON, но версию схемы ниже текущей, поверх
релиза с текущей (более новой) схемой. Ожидание: `NewerSchema` (D-7 rung 7) — приложение стартует с
пустым структурным состоянием на эту сессию, **файл на диске не изменяется**. Переустановка нового
релиза восстанавливает всё без потерь (см. `Storage/rollback.md` сценарий B).

### S-7 — Fast User Switching (закрывает ADR-023 R-15 на живой системе)

1. Пользователь A запускает приложение (создаёт панель, ждёт сохранения).
2. Через «Переключить пользователя» (не «Выйти») войти как пользователь A во вторую сессию Windows
   и запустить приложение снова.
3. Ожидание: второй процесс — degraded read-only (`StateStoreLockUnavailable` в диагностике, один раз
   в `Console.Error`), приложение не падает и не показывает модальных диалогов (ADR-023 §8). Переключиться
   обратно на первую сессию — панели там на месте, `application-state.json` не повреждён.

### S-8 — жёсткое отключение питания / `Stop-Process -Force`

Во время активного drag/resize панели (значит, отложенная запись в `SaveScheduler` вот-вот должна
сработать) выполнить `Stop-Process -Force` на процессе (или физически отключить питание ноутбука, если
воспроизводится на реальном железе). После перезапуска — `application-state.json` либо старая, либо
новая валидная версия (никогда не усечённый/повреждённый JSON) — закрывает D-6/R-1 на уровне реальной
ОС, а не только инъецированных точек отказа `AtomicJsonFileWriterTests`.

### S-9 — `--restore-state-backup` на битом primary

1. Создать несколько панелей, дождаться сохранения (появляется `.bak`).
2. Вручную испортить `application-state.json` (оборвать JSON).
3. Запустить `DesktopOrganizer.exe --restore-state-backup` из терминала.
4. Ожидание: код выхода `0`, сообщение об успехе в консоли и в message box, `application-state.json`
   восстановлен из `.bak`, испорченный файл — в `application-state.corrupt-*.json` (не удалён).
5. Обычный запуск после этого — `Loaded`, все панели на месте.

### S-10 — Controlled Folder Access / сторонний AV

Включить Controlled Folder Access (Windows Security → Ransomware protection) без явного разрешения для
`DesktopOrganizer.exe`, либо воспроизвести на машине со сторонним AV, агрессивно блокирующим запись в
`%LOCALAPPDATA%`. Ожидание: запись деградирует (после исчерпания retry — `StateSaveFailed` в
диагностике, `errorType` без пути/сообщения исключения), приложение не падает и продолжает работать в
памяти; после снятия блокировки следующая запись проходит нормально.

### S-11 — перф: время старта не хуже базлайна

```powershell
./tools/perf/New-PerfFixture.ps1 -Panels 50 -ItemsPerPanel 100
./tools/perf/Measure-Startup.ps1
./tools/perf/New-PerfFixture.ps1 -Restore
```

Сравнить с базлайном Фазы 0 (`Testing/performance-baseline-template.md`) — стартовое время не должно
заметно вырасти из-за добавленного JSON-парсинга/миграции/лока по сравнению со старым XML-путём.
