# P1 — Fit-to-content, сохранение размеров и переход старых раскладок

**Роль:** senior .NET/WPF engineer, Windows shell integration. Следуй `AGENT_CONTRACT.md`. **Вход:** текущий репозиторий, текущий скрин и третий Ambient Accent референс; не переносить размеры с картинки как доказанные константы.

**Зависимость:** результаты этапа 05; не приступай до его DoD. **Вне рамок:** рефакторинг не затронутых модулей, новые продуктовые фичи, переписывание UI на другом фреймворке, полная замена WorkerW/хранилища.

## Задание
Добавь явное действие `Fit panel to content`, опциональный режим `AutoContent` и режим `Manual`, не уничтожая намеренно пустое место в ручных панелях. Вычисление: header + padding + rows×slotHeight + rowGaps, затем округление до workspace row span; число строк зависит от доступной ширины/column capacity, без циклического feedback layout. Для одной иконки auto-content не создаёт экранный высокий прямоугольник; для пустой панели остаётся минимальная видимая drop zone. Зафиксируй правила изменения при добавлении/удалении иконок, смене вкладки/набора, roll-up, list mode и screen resize. Существующие saved dimensions и snapshot JSON должны сохраниться, миграция должна быть безопасной, idempotent и с rollback.

## Выходные артефакты
UI action + `PanelSizingMode`, versioned mapping/persistence, тесты миграции и поведения AutoContent/Manual, документация «не трогать ручные размеры».

## Definition of Done
AutoContent корректно подбирает 0/1/2 ряда и не отрезает подписи; Manual сохраняет высоту при изменении количества иконок; legacy не меняется без opt-in; импорт/экспорт и snapshots после двух циклов restore одинаковы.
