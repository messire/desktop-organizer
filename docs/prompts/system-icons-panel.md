# Фича: SystemIconsPanel — независимая панель системных иконок

## Задача
Добавить **новое независимое окно** `SystemIconsPanel` (рабочее имя `ControlPanel`) —
вертикальная панель, приклеенная к **левому краю основного монитора** на всю высоту,
для отображения **системных иконок** (Этот компьютер, Панель управления, Корзина, Сеть,
Профиль пользователя и т.п.). Это **не** ChildWindow/Fence — отдельный тип окна со своим
ViewModel и своей моделью, **не** завязанный на `ChildWindowModel` и не участвующий в логике
фенсов (snapping, roll-up, layout-сохранение фенсов).

Цель — паритет с поведением подобных панелей в Stardock Fences. См. CLAUDE.md и docs/ROADMAP.md.

## Поведение окна
- **Уровень desktop (как фенс):** окно живёт на уровне рабочего стола, **за** обычными
  прикладными окнами (тот же подход к Z-order, что у существующих ChildWindows — крепление
  к WorkerW/Progman). Место под обычные окна **не резервируется** (это НЕ AppBar).
- **Позиция:** левый край **основного** монитора, высота = вся рабочая высота монитора.
- **Ширина:** равна ширине иконок + отступы (auto-size по содержимому, без ручного ресайза
  по ширине).
- **Мультимонитор:** только основной монитор (одна панель). Заложить возможность расширения
  на «выбор монитора» позже, но сейчас — только Primary.
- **Без заголовка, без рамки**, перетаскивание/закрытие окна пользователем не предусмотрено
  (видимостью управляет глобальный тоггл).

## Содержимое
- **Системные иконки** (фиксированный набор), каждая включается/выключается отдельно в общих
  настройках:
  - Этот компьютер (This PC)
  - Панель управления (Control Panel)
  - Корзина (Recycle Bin)
  - Сеть (Network)
  - Профиль пользователя (User folder)
- **Иконки тянуть нативно** из shell (через `INativeApi`: `SHGetFileInfo` / known-folder CLSID,
  `IDL`-pidl для системных элементов), а не хардкодить картинки.
- **Корзина с состоянием:**
  - Иконка отражает состояние **заполнена/пуста** (`SHQueryRecycleBin`), обновляется при
    изменениях.
  - Поддержка **drop файлов на Корзину** → удаление (перемещение в корзину) перетащенных
    элементов.

## Взаимодействие
- **Двойной клик** по иконке → открыть элемент (как в Проводнике; через shell-execute pidl).
- **Контекстное меню (ПКМ)** → нативное системное контекстное меню элемента
  (Свойства, Открыть, для Корзины — «Очистить корзину» и т.п.), через shell context menu
  (`IContextMenu`).
- **Drag-reorder** → перетаскивание иконок внутри панели меняет их порядок; порядок
  сохраняется в конфиг.

## Вид иконок
- Режим **иконка + подпись** (текст под иконкой).
- **Размер иконок настраивается** в общих настройках (S / M / L). Ширина панели
  пересчитывается под выбранный размер.

## Настройки (в общих настройках приложения)
- **Глобальный тоггл** «Показывать панель системных иконок» (вкл/выкл всю панель).
- Чекбоксы видимости по каждой системной иконке.
- Выбор размера иконок (S/M/L).
- Хранение конфига — в **общем JSON persistence** проекта, **отдельной секцией**
  (например `SystemIconsPanel`): тоггл, набор включённых иконок, их порядок, размер.

## Инварианты и ограничения (из CLAUDE.md)
- Любой P/Invoke только за `INativeApi`.
- Колбэки/хуки — минимум работы + try/catch.
- Битые/недоступные системные элементы не должны валить загрузку панели — деградировать
  молча (скрыть пункт / плейсхолдер-иконка).
- Слои: модель в `Core`, интерфейс сервиса в `Services.Abstractions`, реализация +
  shell-interop в `Services/Tools/`, UI в `UI` (View/ViewModel/Converters).
- Нативный/WPF-код не выполняется вне Windows → отметить пункты «manual verify (Win10/Win11)».

## Критерии готовности (Definition of Done)
1. Панель появляется на левом краю основного монитора на всю высоту, ширина по содержимому,
   за обычными окнами.
2. Системные иконки отображаются с нативными значками и подписями; видимость каждой и размер
   управляются из общих настроек; глобальный тоггл скрывает/показывает панель.
3. Двойной клик открывает элемент; ПКМ показывает нативное контекстное меню; иконки
   переупорядочиваются drag-and-drop, порядок сохраняется.
4. Корзина отражает заполнена/пуста и принимает drop для удаления.
5. Конфиг (тоггл, набор, порядок, размер) сохраняется/восстанавливается из общего JSON.
6. `dotnet build` и `dotnet test` зелёные; покрытие на сервис-слой; список «manual verify».
